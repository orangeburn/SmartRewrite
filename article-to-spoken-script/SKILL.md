# 文章转口播稿

把文章重组为听众第一次听就能跟上的口播稿。通过交流结构、听觉导航和节奏建立口播感，不堆砌“其实”“大家好”等填充词。

## 接收输入

- 获取完整原文；输入只有标题、摘要或片段时，先请用户补充全文。
- 使用用户提供的标题、背景、目标受众、时长、节目形式、语速或 TTS 要求；未提供时不强求。
- 用户给出文件、链接或数据源时，读取其中的完整正文。不要假设任何固定数据库、字段名或存储方式。
- 用户要求指定时长时，按其语速要求估算；未指定语速时，以自然中文口播约每分钟 200 至 240 字作为粗略参考，并优先保证论证完整。

## 提炼原文

改写前在内部确认：

1. 核心判断，以及听众最终应记住的一句话。
2. 文章纠正或反对的观点。
3. 支撑结论的事实、案例、前提和推理顺序。
4. 作者的立场、情绪基调和有辨识度的表达。
5. 可压缩的重复、支线和视觉性内容。

无法概括核心时，先重新理解原文，不要开始续写。

## 保持忠实

- 保留核心观点、关键事实、案例、论证前提、重要转折、价值判断和作者风格。
- 区分个人经历、推测和普遍事实，不要改变其确定程度。
- 不补充原文没有的事实，不虚构案例，不替作者完善结论，不把文章改成主题相近的新文章。
- 不因追求温和、专业或“正能量”而削弱讽刺、批判或明确判断。
- 可以调整顺序和措辞，但调整后必须保持原有因果关系与结论。

## 重建听觉结构

不要逐段机械口语化。按一条连续的理解路径组织内容：

1. 用原文已有的问题、矛盾、现象、故事或判断尽快进入主题。
2. 说明要讲清什么，以及为什么值得听。
3. 依次展开事实、案例和观点。
4. 在转折处用自然语言说明前后关系。
5. 回到核心判断，用一句有记忆点的话收束。

让每一段主要承担一种功能：提出问题、给出判断、解释、举例或阶段性总结。优先使用“观点 → 解释 → 例子 → 结论”或“现象 → 疑问 → 原因 → 判断”。

只在确有结构作用时加入“问题就在这里”“先看一个例子”“换句话说”“回到最开始的问题”等导航。可以预判听众疑问，但只能回应原文逻辑支持的问题。

## 调整语言与节奏

- 以短句和中等长度句为主，一个句子只承载一个主要意思。
- 明确主语和指代，拆开多层定语、括号补充和并列判断。
- 连续出现抽象判断时，使用原文已有的例子、场景、类比或一句总结降低密度；没有依据时不要新造事实性例子。
- 让短句负责强调，中等长度句负责解释；避免每句等长，也不要每几个字就换行。
- 每段通常包含一至四个完整句子，以自然朗读节奏分段。
- 保留作者的直接、克制、讽刺、自我怀疑或其他鲜明特征，避免主持人腔、新闻播音腔、讲师腔和标准化 AI 文风。

除非用户明确要求，不加入节目寒暄、关注引导、结束套话或无信息量的设问。

## 压缩内容

指定时长或篇幅需要压缩时，优先删减：

- 重复表达同一观点的段落。
- 依赖视觉排版的内容。
- 过长背景、弱相关支线和同类案例。
- 不影响听觉理解的精确细节与补充说明。

不得删除核心论点、关键事实、必要前提、重要转折、明确立场或体现作者风格的关键表达。删减可能改变结论时，保留内容。

## 适配 TTS

仅在用户要用于 TTS 或直接朗读时进行以下处理：

- 用标点、分句和换行形成自然停顿，不加入可能被读出的舞台提示。
- 将符号、日期、货币、百分比、单位和复杂数字改成语境中自然且不失真的读法。
- 检查英文缩写、专有名词和多音字；首次出现时在不改变原意的前提下提供易读形式。
- 避免连续堆叠英文或数字；必要时拆句。
- 不擅自把精确数字模糊化。只有精度不影响原意时，才可将其改成“约”“不到”等听觉友好的表达。

不要加入 `[停顿]`、`[重读]`、`[笑]`、`[音乐起]` 等标记，除非用户指定的工具明确支持并要求这些标记。

## 输出

- 默认只输出标题和完整口播正文，不展示分析、提纲或修改说明。
- 不使用章节编号或 Markdown 表格；长稿只有在用户明确要求时才保留章节结构。
- 不添加原文没有且用户未要求的开场、结尾、行动号召或平台话术。
- 用户要求保存或关联到外部系统时，将其视为独立的后续交付；仅在目标位置和关联方式明确且工具可用时执行。

## 自检

提交前默读一遍并检查：

- 核心观点、事实、立场、推理和作者声音是否保持不变。
- 是否加入了无依据的信息，或把个人经验写成普遍事实。
- 第一次听是否能跟上，转折和指代是否清楚。
- 是否存在必须回看文字才能理解的长句、数字或括号。
- 是否滥用填充词、设问、套话或舞台提示。
- 开头是否迅速进入问题，结尾是否完成收束。
- 指定时长、受众、节目形式和 TTS 要求是否得到满足。
