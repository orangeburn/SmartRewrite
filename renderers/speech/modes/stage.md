# Stage Mode

## 一、任务定义

Stage Mode 是 Speech Renderer 面向真人现场演讲的输出模式。

适用于：

- 上台演讲；
- 分享会；
- 公开表达；
- 线下培训；
- 圆桌发言；
- 使用纸稿或平板辅助演讲；
- 需要根据现场反应进行一定自由演绎的表达场景。

Stage Mode 将演讲结构、顺序、必要信息和阶段落点外置到讲稿中。

演讲者无需持续在工作记忆中维护：

- 下一段是什么；
- 当前还缺什么信息；
- 当前案例承担什么作用；
- 当前表达最后落在哪里；
- 什么时候进入下一部分。

演讲者低头查看讲稿后，应能够迅速恢复当前表达任务。

---

## 二、核心原则

Stage Mode 的核心状态是：

**眼睛看到结构，嘴巴完成表达。**

Stage Mode 不固定演讲者的每一句话，而是固定：

- 演讲任务；
- 信息边界；
- 关键支撑；
- 推理方向；
- 阶段落点。

Stage Mode 的控制粒度是：

**接下来这一小段，需要把什么事情讲明白。**

Stage Mode 不以逐句跟读为目标。

---

## 三、基本输出单位

Stage Mode 的基本输出单位是：

**最小充分演讲块。**

### 3.1 定义

最小充分演讲块，是一组围绕同一个表达任务组织的信息。

它需要包含足够的信息，使演讲者无需重新构建主要论证，即可自由完成这一小段演讲。

一个演讲块至少应让演讲者迅速确认：

1. 当前在讲什么；
2. 哪些信息不能遗漏；
3. 这些信息之间是什么关系；
4. 当前表达最后落到哪里。

信息不足时，演讲者需要依赖记忆或临场推理补全逻辑。

信息过多时，演讲者容易转为逐句朗读。

核心判断：

**再少一点，需要用脑子补；再多一点，开始用嘴念。**

---

## 四、视觉触发

Stage Mode 的讲稿首先是一套视觉表达系统。

演讲者不需要完整阅读一个演讲块，便应能够识别当前表达任务。

目标状态：

**扫一眼，表达被触发。**

每个演讲块包含三层视觉信息。

### 4.1 块主题

块主题用于帮助演讲者瞬间确认当前表达任务。

块主题应描述当前这一小段要完成的事情，而不是只重复文章标题或概括话题。

### 4.2 必要信息

必要信息是当前演讲块不能遗漏的内容。

这些信息应保留：

- 对象；
- 判断；
- 原因；
- 条件；
- 对比；
- 结果；
- 必要关系。

必要信息必须保持完整语义。

不得退化成缺少关系的关键词堆叠。

### 4.3 阶段落点

每个演讲块都需要明确的阶段落点。

阶段落点用于：

- 完成当前表达任务；
- 限定当前表达范围；
- 帮助演讲者结束当前块；
- 帮助演讲者进入下一块。

阶段落点不要求逐字复现。

---

## 五、演讲块内部结构

一个标准演讲块包含：

```text
块主题

必要信息
必要信息
必要信息

阶段落点
```

最终输出不需要机械显示“必要信息”“阶段落点”等标签。

视觉层级需要让演讲者快速识别：

**主题 → 支撑 → 落点**

演讲块内部允许演讲者自由调整措辞和局部顺序，但不得改变当前块的表达任务和语义边界。

---

## 六、演讲块拆分

Stage Mode 不按照固定字数拆块。

判断标准：

**一个演讲块只完成一个阶段性表达任务。**

出现以下情况时，应考虑进入新的演讲块。

### 6.1 核心判断变化

当前表达开始承担新的主要判断时，建立新块。

### 6.2 表达任务变化

当内容从一种任务切换到另一种任务时，应重新判断块边界。

表达任务包括：

- 提出问题；
- 解释原因；
- 建立对比；
- 展开案例；
- 说明结果；
- 回收主线；
- 得出阶段结论；
- 进入新的讨论方向。

### 6.3 案例开始承担独立证明作用

案例仅用于辅助理解时，可以保留在当前块。

案例需要独立展开并承担重要证明作用时，应形成独立演讲块。

### 6.4 进入新的对象或比较关系

讨论对象发生明显变化，或进入新的对比关系时，应检查是否需要建立新块。

### 6.5 当前阶段判断已经成立

一个演讲块完成明确落点后，应结束当前块。

不得继续向同一块堆入新的独立推理任务。

---

## 七、演讲块合并

以下情况应优先合并。

### 7.1 多个部分共同完成一个判断

拆开以后无法独立形成完整表达任务时，应合并。

### 7.2 后一部分只是前一部分的必要解释

后一部分不承担新的主要任务时，无需单独形成演讲块。

### 7.3 分块增加记忆负担

如果演讲者进入新块后，必须依赖对上一块具体句子的记忆才能理解当前内容，说明块边界需要重新调整。

---

## 八、演讲块大小

Stage Mode 不设置固定字数。

一个演讲块应满足：

**演讲者能够在一次扫视中识别它的结构。**

演讲者不需要一次读完全部内容，但应快速识别：

- 当前主题；
- 主要信息；
- 阶段落点。

当一个块形成大面积文字墙时，应重新组织。

当大量演讲块只剩一两句话时，应检查是否已经过度碎片化。

---

## 九、信息层级

Stage Mode 不要求所有文字具有相同视觉权重。

### 9.1 一级信息：演讲任务

一级信息需要最容易被识别。

它用于确认当前演讲块要完成什么。

### 9.2 二级信息：必要支撑

二级信息用于保证当前判断或表达任务成立。

必须保持完整语义。

### 9.3 三级信息：辅助内容

三级信息包括：

- 可选案例细节；
- 次要描述；
- 补充背景；
- 可根据现场展开的信息。

三级信息允许根据现场情况适当省略。

省略后不得破坏当前块的核心判断、必要关系和阶段落点。

### 9.4 阶段落点

阶段落点具有较高视觉权重。

演讲者需要能够快速找到当前块的收束位置。

---

## 十、重新定位

Stage Mode 必须允许演讲者较长时间脱离讲稿。

演讲者可能：

- 看观众；
- 临时解释；
- 回应现场；
- 加入例子；
- 停顿；
- 做手势；
- 进行互动。

重新查看讲稿时，应能够迅速恢复当前位置。

重新定位主要依赖：

**块主题 → 当前支撑点 → 阶段落点**

定位不得依赖记住上一句具体说到哪里。

---

## 十一、演讲者自由度

Stage Mode 允许演讲者在演讲块内部进行自由演绎。

允许：

- 改变措辞；
- 调整局部语序；
- 增加自然连接；
- 重复关键判断；
- 根据观众反应改变节奏；
- 临时多解释一句；
- 使用现场类比；
- 略过不影响核心判断的辅助内容；
- 改变案例内部的表达方式。

不得破坏：

- 原文事实；
- 核心判断；
- 因果关系；
- 条件和限制；
- 判断强度；
- 不确定性；
- 概念边界；
- 关键证据；
- 当前演讲块的阶段落点。

Stage Mode 提供：

**局部表达自由，不提供观点自由。**

---

## 十二、记忆负担外置

Stage Mode 将演讲者的工作记忆负担外置到讲稿中。

以下信息应尽量由讲稿承担：

- 演讲顺序；
- 论证结构；
- 关键数据；
- 人名；
- 公司名；
- 专业词；
- 多项并列信息；
- 案例中的关键关系；
- 强判断前的必要条件；
- 阶段结论；
- 下一演讲块的主题。

演讲者的注意力主要用于：

- 观察观众；
- 控制语气；
- 调节节奏；
- 临场组织措辞；
- 判断是否展开；
- 完成现场互动。

核心原则：

**稿件负责记忆，演讲者负责表达。**

---

## 十三、视觉排版

Stage Mode 的排版目标是：

**最快触发表达。**

### 13.1 一个演讲块形成一个明确视觉区域

不同演讲块之间保留清晰边界。

### 13.2 块主题需要突出

演讲者快速翻页或低头查看时，应优先找到块主题。

### 13.3 关键概念允许视觉强调

视觉强调用于快速检索。

不得因为视觉强调改变原有语义权重或判断强度。

### 13.4 避免大段正文墙

排版不得诱导演讲者逐句跟读。

### 13.5 避免过度碎片化

排版不得退化为大量孤立句子或关键词。

### 13.6 阶段落点需要容易识别

演讲者完成自由发挥后，应能够快速找到当前块的收束位置。

### 13.7 分页不得破坏演讲块结构

用于打印、平板或其他分页介质时，应尽量保持一个演讲块的核心结构完整。

---

## 十四、Stage Mode 执行协议

Stage Mode 只在 Speech Renderer 已完成以下 Core / Speech 中间结果后执行：

- Fidelity Contract；
- 概念锚词；
- 内容单元；
- 内容依赖关系；
- 演讲路径；
- 最小充分表达单元。

执行过程默认属于内部处理，不向用户输出中间分析。

### 第一步：读取演讲路径

按照已经确定的演讲顺序，逐个读取最小充分表达单元。

不得重新从文章段落直接开始分块。

输出：

**有序表达单元序列。**

### 第二步：标记每个表达单元的作用

为每个表达单元确定其主要作用：

- 问题；
- 事实；
- 判断；
- 原因；
- 条件；
- 对比；
- 案例；
- 结果；
- 限定；
- 回收；
- 阶段结论；
- 最终结论。

一个表达单元只标记一个主要作用。

如果同时承担多个主要作用，先返回 Speech 层重新拆分。

输出：

**带作用标记的表达单元序列。**

### 第三步：识别阶段性演讲任务

从第一个表达单元开始向后读取。

连续单元如果共同回答同一个阶段性问题、支持同一个判断或完成同一个表达目标，则归入同一候选演讲块。

遇到以下边界时停止聚合：

- 核心判断改变；
- 表达对象改变；
- 推理任务改变；
- 独立案例开始；
- 新对比开始；
- 当前阶段已经形成明确落点。

输出：

**候选演讲块。**

### 第四步：检查候选块是否只有一个主要任务

对每个候选块回答：

**这一块讲完以后，听众应该多知道、理解或接受什么？**

答案必须能够用一个清楚的阶段目标表达。

如果存在两个互不依赖的答案：拆块。

如果无法形成完整答案：与相邻块重新合并。

输出：

**单任务演讲块。**

### 第五步：确定块主题

根据当前演讲任务生成视觉锚点。

块主题需要满足：

- 扫一眼能恢复上下文；
- 能区分前后演讲块；
- 能提示这一块的表达任务；
- 不依赖上一块才能理解；
- 不引入母稿不存在的新判断。

块主题不是正文摘要，也不是修辞性标题。

输出：

**块主题。**

### 第六步：区分必要信息与辅助信息

逐项检查当前演讲块中的表达单元。

如果删除某项会导致以下任何结果，则标记为必要信息：

- 事实缺失；
- 判断无法成立；
- 因果断裂；
- 条件消失；
- 限定消失；
- 对比失效；
- 案例失去证明作用；
- 概念边界改变；
- 判断强度变化；
- 阶段落点无法成立。

其余可以支持现场展开、但省略后不破坏核心语义的信息，标记为辅助信息。

输出：

**必要信息层 + 辅助信息层。**

### 第七步：确定阶段落点

识别当前演讲块完成以后必须留下的阶段结果。

阶段落点必须来自：

- 母稿已有判断；
- 当前演讲路径已有结论；
- 当前信息关系自然形成的已有结论。

不得为了增强演讲效果重新制造结论。

如果当前块找不到明确落点：重新检查块边界。

输出：

**阶段落点。**

### 第八步：生成第一版演讲块

按照以下结构生成：

```text
块主题

必要信息

辅助信息

阶段落点
```

生成时：

- 保留完整语义；
- 降低逐字朗读诱因；
- 保留足够的词汇自由；
- 保留关键概念锚词；
- 不压缩为关键词；
- 不写成连续正文段落。

输出：

**第一版 Stage Block。**

### 第九步：执行“用眼睛演讲”检查

只查看当前 Stage Block，不查看母稿。

模拟演讲者低头扫视。

检查能否立即确认：

1. 现在讲什么；
2. 从哪里开始；
3. 哪些信息不能漏；
4. 信息之间怎么推进；
5. 最后说到哪里。

任意一项无法迅速确认：重新调整视觉结构或信息完整度。

输出：

**可视觉触发的 Stage Block。**

### 第十步：执行自由演绎检查

模拟演讲者不按照当前文字逐句表达。

允许主动改变：

- 措辞；
- 语序；
- 连接方式；
- 句子长度；
- 局部展开方式。

检查改变以后是否仍能：

- 完成当前任务；
- 保留必要信息；
- 保留判断强度；
- 保留关系；
- 回到阶段落点。

如果只有照着文字念才能保持结构：当前演讲块过度完整，重新压缩表达控制。

如果自由表达后容易漏掉主要内容：当前演讲块信息不足，重新补足必要信息。

### 第十一步：执行脱离与重新定位检查

模拟演讲者在当前块中途：

- 抬头离开讲稿；
- 自由表达一段；
- 加入现场解释；
- 与观众互动；
- 再次低头。

重新查看讲稿时，应能够通过视觉结构判断：

- 当前正在第几个演讲任务；
- 哪些信息已经讲过；
- 接下来还要讲什么；
- 当前块如何结束。

如果必须回忆“上一句念到哪里”：重新设计块内部层级。

### 第十二步：执行相邻块连接检查

逐对检查相邻演讲块。

确认：

- 前一块已经完成自己的任务；
- 后一块能够独立启动；
- 两块之间存在清楚的信息关系；
- 演讲者不需要背连接句才能切换；
- 不存在同一判断被错误拆开；
- 不存在上一块的必要信息被放到下一块。

必要时重新拆块、合块或调整顺序。

### 第十三步：执行整篇视觉密度检查

从整篇讲稿视角检查：

- 是否存在过大的文字墙；
- 是否存在大量只有一两句话的小块；
- 块主题是否容易彼此区分；
- 关键数据和概念是否能够快速检索；
- 阶段落点是否容易找到；
- 页面视觉节奏是否支持抬头与低头切换。

发现局部问题时，只调整对应演讲块。

不得因为排版问题重新改变整篇观点结构。

### 第十四步：执行语义覆盖对比

按照 [`../references/semantic-coverage.md`](../references/semantic-coverage.md) 对最终 Stage 稿执行双向 Fidelity 检查。

发现缺失或变化时，返回对应 Stage Block 修复。

修复以后重新执行本步骤。

### 第十五步：执行完整演讲模拟

按照最终 Stage Block 顺序，从头到尾模拟一次现场演讲。

模拟过程中不逐句朗读，只根据每个演讲块完成表达。

检查：

- 是否能够自然开始；
- 是否存在需要临场重新组织论证的位置；
- 是否有块内信息过多；
- 是否有块内信息不足；
- 是否频繁依赖记忆；
- 是否能够自然抬头；
- 是否能够自由发挥；
- 是否能够快速回来；
- 是否能够明确结束每一块；
- 是否能够顺利进入下一块。

出现问题时返回具体演讲块修改。

### 第十六步：最终输出

最终只输出完成后的 Stage 稿。

默认不输出：

- 内容单元分析；
- 块划分理由；
- 信息层级标签；
- 语义覆盖表；
- 检查过程；
- 修改过程；
- 执行说明。

除非用户明确要求查看这些过程。

---

## 十五、失败回退规则

Stage Mode 不通过检查时，不允许直接输出当前结果。

### 语义缺失

回到语义覆盖对比，恢复缺失信息。

### 一个块包含多个任务

回到演讲任务识别，重新拆块。

### 块过碎

回到候选块聚合，重新合并。

### 块形成正文墙

回到信息层级和视觉结构，重新组织。

### 必须逐字读才能成立

回到第一版演讲块生成，降低措辞控制。

### 演讲者不知道怎么展开

回到必要信息识别，增加完整关系。

### 自由发挥后容易跑题

重新强化块主题和阶段落点。

### 无法快速重新定位

重新调整块主题、信息层级和视觉边界。

### 相邻块切换困难

回到相邻块连接检查，调整块边界或顺序。

任何修复完成后，都必须重新执行：

**自由演绎检查 → 重新定位检查 → 语义覆盖检查。**

---

## 十六、Stage Mode 验收标准

合格的 Stage 稿必须满足：

1. 演讲者无需提前背稿；
2. 低头扫视即可确认当前演讲任务；
3. 每个演讲块只有一个主要阶段目标；
4. 每个演讲块包含支持该任务所需的完整信息；
5. 演讲者无需临场重新构建主要论证；
6. 演讲者可以明显改变措辞而不破坏内容；
7. 演讲者可以在块内自然展开；
8. 演讲者脱离讲稿后能够快速重新定位；
9. 讲稿不依赖对上一句具体措辞的记忆；
10. 页面不存在大量正文墙；
11. 页面不存在大量碎片化关键词；
12. 演讲者无需持续低头跟随文字；
13. 关键数据、概念和判断可以快速视觉检索；
14. 每个演讲块都有清楚的收束位置；
15. 母稿有效语义没有因聚合、压缩或自由度增加而丢失；
16. 最终状态属于“看稿演讲”，不是“拿稿朗读”；
17. 通过 Speech Semantic Coverage 检查。

---

## 十七、最终定义

**Stage Mode 将连续的 Speech 表达单元聚合为能够通过视觉直接触发表达的最小充分演讲块。**

**稿件负责保存结构、顺序和必要信息，演讲者负责现场措辞、节奏和演绎。**

**Stage Mode 让演讲者用眼睛完成演讲。**
