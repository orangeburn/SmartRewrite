# Speech Renderer

## 一、任务定义

Speech Renderer 用于把正式文章重建为适合真人表达的演讲稿。

Speech Renderer 遵守 SmartRewrite Core。

输入必须回到原始母稿，不允许以 TTS Renderer、其他 Renderer 或其他转写结果作为母稿。

Speech Renderer 继承 Core 已建立的：

- Fidelity Contract；
- 概念锚词；
- 内容单元；
- 内容依赖关系。

Speech Renderer 在这些内容结构上建立真人表达路径。

## 二、输出目标

Speech Renderer 的交付目标是：

**信息已经完成，真人负责最后表达。**

Speech Renderer 不固定唯一措辞。

它必须让演讲者在不重新构建主要事实、观点、关系和论证的前提下，自然完成最终表达。

普通措辞、局部语序、连接方式和现场节奏可以由演讲者调整。

原文事实、判断、关系、条件、判断强度、不确定性、概念边界和最终结论必须保持稳定。

## 三、核心转换模型

```text
Original Source
↓
SmartRewrite Core
↓
Fidelity Contract
内容单元
内容依赖关系
概念锚词
↓
Speech 演讲路径
↓
最小充分表达单元
↓
口头表达适配
↓
Mode Routing
├─ Teleprompter Mode
└─ Stage Mode
↓
Speech Semantic Coverage
↓
最终成稿
```

Speech Renderer 的共用语义层结束于：

**最小充分表达单元。**

Mode 只负责把这套已经完成的信息结构呈现为不同的人类表达形式。

## 四、演讲路径

Speech Renderer 不直接沿用原文段落顺序。

需要根据 Core 内容依赖关系，把母稿重建为一条真人能够顺着讲下去的演讲路径。

### 4.1 前提先于依赖它的判断

听众理解当前内容所需的必要信息应提前出现。

### 4.2 同一问题尽量连续完成

同一条推理中的事实、判断、原因、案例、条件和结论尽量保持邻近。

### 4.3 判断与证据保持邻近

案例、数据和解释应靠近它们所支持的判断。

### 4.4 限制条件靠近强判断

母稿中的条件、例外、保留和不确定性应靠近相关判断。

### 4.5 主题切换必须能够重新定位

进入新的讨论方向时，需要让演讲者和听众同时确认当前讨论对象和任务。

## 五、最小充分表达单元

最小充分表达单元，是一个包含完整命题和必要关系、只承担一个主要表达动作，并允许演讲者自由完成最终措辞的信息单元。

每个单元必须满足：

1. 有完整命题；
2. 包含判断成立所需的必要对象、原因、条件、对比或结果；
3. 只有一个主要表达动作；
4. 不退化成关键词提示；
5. 不依赖唯一措辞才能成立；
6. 演讲者看到后可以直接开始表达；
7. 改变自然措辞后仍能进入后续内容。

核心判断：

**再少一点，演讲者需要临场组织内容；再多一点，演讲者开始被迫阅读句子。**

## 六、表达单元的拆分与合并

### 应拆分

- 同时存在两个独立判断；
- 一个部分必须先被理解，另一部分才能成立；
- 条件、原因和结论挤在复杂句法中；
- 存在多个表达重心；
- 演讲者无法自然一口进入表达。

### 应合并

- 单元退化成关键词；
- 单元只有关系提示，没有完整命题；
- 多个单元共同才能表达一个完整意思；
- 拆分后反而增加对上一单元的记忆依赖。

核心标准：

**一眼只需要抓住一个主要表达动作。**

## 七、口头表达适配

Speech Renderer 需要降低书面句法摩擦，但不固定最终措辞。

优先呈现直接关系：

**谁 → 做什么 → 为什么 → 导致什么。**

允许：

- 自然换词；
- 调整局部语序；
- 增加简单连接；
- 局部重复核心概念；
- 根据现场语气调整句子长度。

承担概念边界和核心判断的锚词保持稳定。

## 八、Mode Routing

Speech Renderer 有两种正式输出模式。

### 8.1 Teleprompter Mode

完整规则见：

[`modes/teleprompter.md`](./modes/teleprompter.md)

适用于：

- 提词器；
- 播客录制；
- 视频录制；
- 第一次表达；
- 希望细粒度控制连续信息路径的场景。

控制粒度：

**这一刻完整要表达什么。**

默认情况下，如果用户没有指定模式，使用 Teleprompter Mode。

### 8.2 Stage Mode

完整规则见：

[`modes/stage.md`](./modes/stage.md)

适用于：

- 上台演讲；
- 分享会；
- 公开表达；
- 使用纸稿或平板；
- 希望保留较大现场演绎空间的场景。

控制粒度：

**接下来这一小段需要把什么事情讲明白。**

Stage Mode 将连续表达单元进一步聚合为最小充分演讲块，让讲稿承担结构和记忆负担，使演讲者能够通过视觉触发表达。

Stage Mode 只有在用户明确选择、或用户明确描述上台演讲、拿稿演讲、自由演绎等需求时启用。

## 九、共用语义覆盖

所有 Speech Mode 都必须执行双向 Fidelity 检查。

完整规则见：

[`references/semantic-coverage.md`](./references/semantic-coverage.md)

必须同时确认：

- Output → Source：输出没有新增母稿不存在的命题或关系；
- Source → Output：母稿有效语义没有因场景重建而丢失。

语义覆盖属于内部验收流程，默认不向用户输出覆盖表和检查过程。

## 十、Speech Renderer 执行协议

### 第一步：读取原始母稿和用户约束

读取完整原始母稿，不依赖标题、摘要、标签或其他 Renderer 输出。

确认用户指定的场景、模式、时长和固定表达要求。

### 第二步：读取 Core 结果

读取：

- Fidelity Contract；
- 概念锚词；
- 内容单元；
- 内容依赖关系。

### 第三步：建立演讲路径

根据内容依赖关系重建连续的信息推进顺序。

确保：

- 前提先出现；
- 证据靠近判断；
- 条件靠近强判断；
- 同一问题尽量连续完成；
- 新主题能够重新定位。

### 第四步：生成最小充分表达单元

为每个单元确定：

- 当前主要表达动作；
- 当前完整命题；
- 必要关系；
- 必要概念锚词。

### 第五步：执行拆分与合并

消除：

- 多重表达重心；
- 关键词式碎片；
- 只有连接关系的残句；
- 必须依赖上一单元才能理解的碎片；
- 需要预先规划才能说完的复杂句法。

### 第六步：执行连续性检查

逐对检查相邻表达单元。

确认演讲者能够自然从当前单元进入下一单元，并保留原有因果、条件、对比、递进和主题关系。

### 第七步：执行口头表达适配

降低书面句法摩擦，使每个表达单元达到：

**看到就能开始说。**

### 第八步：执行可偏离性检查

模拟演讲者自然换一种说法。

确认改变措辞后仍能：

- 保留完整意思；
- 保留判断强度；
- 保留必要关系；
- 保留概念边界；
- 顺利进入后续内容。

只有逐字朗读才能成立时，继续重建。

### 第九步：选择输出 Mode

根据用户明确要求执行：

- Teleprompter Mode → [`modes/teleprompter.md`](./modes/teleprompter.md)
- Stage Mode → [`modes/stage.md`](./modes/stage.md)

用户未指定时，使用 Teleprompter Mode。

### 第十步：执行 Mode 专属流程

完整执行所选 Mode 文件中的：

- 结构重建；
- 视觉组织；
- 模拟检查；
- 失败回退；
- Mode 验收。

不得只读取 Mode 定义而跳过执行协议。

### 第十一步：执行 Speech Semantic Coverage

按照 [`references/semantic-coverage.md`](./references/semantic-coverage.md) 将最终稿重新与原始母稿、Fidelity Contract 和 Core 内容单元逐项对比。

发现缺失、关系变化、判断强度变化、条件丢失或概念漂移时，返回对应 Speech 单元或演讲块修复。

修复后重新执行 Mode 验收和语义覆盖。

### 第十二步：最终输出

默认只输出：

- 标题；
- 所选模式的完整 Speech 成稿。

默认不输出：

- Fidelity Contract；
- 内容单元；
- 依赖关系；
- Mode 路由分析；
- 语义覆盖表；
- 检查过程；
- 修改过程。

除非用户明确要求查看。

## 十一、最终验收

所有 Speech 输出必须满足：

1. 原始母稿是唯一母稿来源；
2. 所有输出事实、观点、关系和判断能够回溯到母稿；
3. 母稿所有有效语义都有最终对应表达；
4. 判断强度、不确定性、条件和概念边界保持稳定；
5. 演讲者无需重新构建主要论证；
6. 演讲者不需要逐字复现稿件；
7. 自然改变措辞后信息仍然稳定；
8. 所选 Mode 的结构、视觉和使用场景验收全部通过；
9. 最终听感属于真人表达完整观点，而不是朗读一篇被口语化的文章。

## 最终定义

**Speech Renderer 先把原始母稿重建为完整、可偏离的真人表达结构，再根据实际场景选择呈现方式。**

**Teleprompter Mode 让演讲者沿着信息连续表达。**

**Stage Mode 让演讲者用眼睛完成演讲。**
