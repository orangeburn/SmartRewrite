# SmartRewrite

SmartRewrite 是一个面向内容转写的 AI Skill 项目。

它试图解决一个常见问题：当模型被要求“改写”一篇文章时，往往会把编辑任务理解成重新创作。原文中的观点、节奏和作者声音被标准化表达覆盖，同时出现过度解释、频繁设问、短句堆叠、段落割裂和模板化总结。

SmartRewrite 将不同类型的转写任务拆成边界明确、可以检查的编辑规则。模型需要先识别原文中真正影响目标媒介的问题，再进行最小必要修改，而不是默认重写全部内容。

## 当前能力

仓库目前包含一个 Skill：

### article-to-spoken-script

将中文文章转写成适合播客、音频节目、视频旁白、人工朗读和 TTS 的口播稿。

这个 Skill 采用“保守转写”原则：

- 原句能够自然朗读时，保留原句。
- 保留原文的观点、事实、论证顺序、判断强度和作者风格。
- 重点处理阅读与收听之间的媒介差异。
- 不通过扩写、虚构听众问题或添加套话制造所谓的口播感。

完整规则见 [`article-to-spoken-script/SKILL.md`](./article-to-spoken-script/SKILL.md)。

## 为什么文章不能直接拿来朗读

阅读和收听使用不同的信息接收方式。

读者可以停顿、回看、跳读标题，也可以从排版中判断段落关系。听众只能跟随声音向前移动。一旦没有听清某个概念，后续内容仍会继续进入。

因此，文章转口播真正需要处理的通常不是“书面词汇不够口语”，而是以下问题：

- **指代负担**：文章里的“这、那、它、这种情况”可能要求听众回忆较远的前文。
- **连接不足**：页面上的分段和标题能够组织文章，声音中需要通过核心概念、因果和对比继续推进。
- **句子过载**：多层定语、括号和并列判断会占用过多工作记忆。
- **视觉依赖**：数字、英文缩写、公式、列表和加粗内容可能无法直接通过声音传递。
- **TTS 限制**：标点、数字写法、专有名词和断句会直接影响合成语音的结果。

SmartRewrite 不把这些问题归结为“缺少口语词”，而是把转写视为一次针对目标媒介的编辑。

## 核心设计原则

### 最小必要改动

默认保留原文。只有某个表达在目标媒介中产生理解障碍时，才修改对应部分。

### 原文优先

原文是内容依据。Skill 不补充原文没有的事实，不替作者完善结论，也不把明确判断改成模糊、中性或讨好的表达。

### 连续理解

每一句都需要让听众知道当前讨论对象，以及它与前一句的关系。段落连接优先依靠概念复现、因果延续、对比延续和对象延续。

### 明确指代

当代词指向较远的句子、上一段或一整段抽象论述时，重新说出必要的核心概念。口播允许适度重复名词，以减少听众检索前文的负担。

### 拒绝模型腔

Skill 限制以下常见改写习惯：

- 把一句自然完整的话拆成多个无信息增量的短句。
- 自动加入“你可能会问”“问题就在这里”等虚构互动。
- 每段都重新提出问题、解释并总结。
- 为了显得完整而补充新例子、新背景或结尾升华。
- 把作者的表达改成主持人腔、讲师腔或标准化 AI 文风。

## 使用方式

在支持 Skill 目录的环境中，可以直接使用 `article-to-spoken-script` 目录。

在只能配置项目指令的环境中，可以复制 [`SKILL.md`](./article-to-spoken-script/SKILL.md) 的内容，并将需要转写的完整文章作为输入。

推荐指令：

```text
使用 article-to-spoken-script，将下面的文章保守转写成适合直接朗读的口播稿。
保留原文观点、论证顺序和作者语气，只处理听觉环境中的指代、连接、长句、视觉依赖和 TTS 问题。
```

输入应尽量包含：

- 完整文章正文
- 目标用途，例如播客、视频旁白或 GPT-SoVITS
- 目标时长或字数限制，如有
- 必须保留或删除的内容，如有

默认输出只包含标题和完整口播正文。

```text

    ├── SKILL.md

        └── openai.yaml
```

- `SKILL.md` 定义任务边界、执行规则和检查标准。
- `agents/openai.yaml` 提供 Skill 的展示信息和默认调用提示。

## 适用场景

这个 Skill 适合：

- 将公众号文章转换成播客文字稿。
- 将长文章转换成视频旁白。
- 为 GPT-SoVITS 等 TTS 工具准备可直接朗读的文本。
- 保留作者个人风格的内容转写。
- 修正已有口播稿中的指代、断句和段落连接问题。

它不适合：

- 根据一个标题重新创作完整节目。
- 为文章增加新的事实、案例或观点。
- 将原文大幅缩写成短视频脚本。
- 生成主持人互动、表演提示或音效脚本。

这些任务需要独立的 Skill，不应混入口播转写流程。

## 判断结果是否合格

一份合格的转写结果应同时满足：

1. 原文仍然清楚可辨。
2. 作者的观点、判断和语气没有被模型覆盖。
3. 没有为了口语化而无意义扩写。
4. 段落之间存在真实的语义连接。
5. 核心概念得到必要复现。
6. 模糊代词已经被处理。
7. 听众不需要频繁回忆较远的前文。
8. 实际朗读时语言自然、连续。
9. TTS 能够正确处理数字、标点和专有名词。

SmartRewrite 的目标不是让模型写得更多，而是让模型只修改真正需要修改的部分。
