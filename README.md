# SmartRewrite

SmartRewrite 用来把已经写好的中文文章，重建成适合播客、旁白、人工朗读和 TTS 的口播稿。

它不是给原文加几个“其实、所以、你看”，也不是围绕同一个主题重新写一篇更口语的文章。

文章和口播是两种不同的媒介。

文章允许读者停下来、回看、跳读标题，也可以依赖段落、加粗和上下文寻找前文。口播只能沿时间向前。听众听到一句话时，如果理解它所需的前提还没出现，或者“这、它、这个问题”需要回头查找，理解就会中断。

SmartRewrite 做的事情，是在不改变原文事实、观点、概念边界和作者判断的前提下，重新组织信息顺序，再把书面表达重建成真正能说出口的中文。

## article-to-spoken-script

`article-to-spoken-script` 是仓库中的文章转口播 Skill。

完整规则见 [`article-to-spoken-script/SKILL.md`](./article-to-spoken-script/SKILL.md)。

它把一次转写拆成四层：

1. **Content Fidelity**：保留事实、观点、关系、判断强度、概念边界和作者声音。
2. **Conversational Reconstruction**：把文章恢复成一个人面对另一个人解释和思考的过程。
3. **Spoken Syntax Reconstruction**：把仍然像“写出来”的句法，改成日常表达中真的会说出来的中文。
4. **Audio Delivery**：处理指代、句长、数字、英文、标点和 TTS 朗读问题。

核心原则是：

> 最小新增，充分重排，概念稳定，信息紧凑。

## 不是“把文章写口语一点”

自然口播和书面文章的差别，不只在词汇。

同一句话写下来可能很顺，真正说出来却很别扭；一段文章单独看逻辑完整，连续听时却可能缺前提；为了显得口语而把一句话拆成四五句，又会变成“磨半天不进正题”。

SmartRewrite 因此同时处理几类问题。

### 听觉顺序

当前判断需要的前提，应尽量在判断之前出现。

原文可以把定义放在后面、把案例和观点隔开、让标题承担转折；口播不能默认听众会回头查找。必要时可以把原文已有内容前置、合并、拆分或移动。

### 说话动机

相邻句子之间要有真实的推进关系：继续解释、补条件、举例、修正判断、回到主线，或者形成结论。

聊天感不靠固定频率的反问、短梗和自我回应。只有内容本身出现冲突、态度、修正或转折时，这些动作才有理由出现。

一段材料也可以安静地连续讲很久。

### 口语句法

口语化不是故意把句子写碎。

能直接说清的命题，不增加多轮铺垫；书面关联句只有在拆开后更容易说、更容易听时才拆；已经明确的主语可以省略，但不能制造新的指代歧义。

目标是降低句法摩擦，而不是降低信息密度。

### 概念稳定

同一个核心概念默认使用稳定的词。

SmartRewrite 会从当前原文中动态识别核心术语、承担论证作用的关键词，以及容易被近义词替换但范围不同的概念。句子可以重写，概念不能因为“避免重复”而漂移。

口播里重复一个准确的核心词，通常比换一个看似自然的近义词更安全。

### 作者声音

事实、观点、判断强度、不确定性、讽刺、保留意见和原文结论都属于需要保留的内容。

Skill 不自动补行业背景，不新增案例，不制造新金句，也不替作者升华结尾。

## 可以怎么改

在不改变原文命题的前提下，可以：

- 前置理解当前判断所需的解释和条件；
- 合并分散在不同位置的同一条推理；
- 把案例移动到它支持的观点附近；
- 在第一次需要时解释概念；
- 拆开不适合朗读的书面句法；
- 省略已经明确且不会产生歧义的重复信息；
- 复现必要的核心概念；
- 删除重排以后产生的重复；
- 恢复原文能够支持的观察、反应、限定、修正和回收过程。

不能借这些操作增加新的事实、观点、因果、类比或作者经历。

## 不做什么

SmartRewrite 不把“口语感”理解成这些东西：

- 大量“其实、所以、你看、就是说”；
- “你可能会问”之类虚构互动；
- 每隔一段安排一个反问或梗；
- 每句话都拆成短句；
- 为了松弛感增加无信息前奏；
- 同一个意思换几种说法重复一遍；
- 为了避免重复随意替换核心概念；
- 把作者语言改成主持人腔、讲师腔或标准 AI 播客文风。

## 使用方式

在支持 Skill 目录的环境中，直接使用 `article-to-spoken-script`。

如果环境只能配置项目指令，可以复制 [`SKILL.md`](./article-to-spoken-script/SKILL.md) 的内容，再提供完整文章。

最简单的调用方式：

```text
使用 article-to-spoken-script，将下面的文章转写成可以直接朗读的口播稿。
保留原文事实、观点、概念边界、判断强度和作者声音。
不要增加新事实、新案例或新结论。
```

输入最好包含：

- 完整文章正文；
- 用途，例如播客、视频旁白或 GPT-SoVITS；
- 时长或字数限制，如有；
- 必须保留、删除或调整的内容，如有；
- 节目名称、讲述者名称或固定开场语，如需要。

默认只输出标题和完整口播正文，不输出内部分析、重排方案和检查过程。

## 目录结构

```text
SmartRewrite/
├── README.md
└── article-to-spoken-script/
    ├── SKILL.md
    ├── references/
    │   └── conversational-discourse.md
    └── agents/
        └── openai.yaml
```

`SKILL.md` 定义完整转写协议和验收标准。

`references/conversational-discourse.md` 定义聊天式重建、口语句法、信息密度和概念稳定的细化规则。

`agents/openai.yaml` 提供 Skill 的展示信息和默认调用提示。

## 适用场景

适合：

- 公众号文章转播客文字稿；
- 长文章转视频旁白；
- 为 GPT-SoVITS 等 TTS 准备可直接朗读的文本；
- 修正已有口播稿里的书面句法、模糊指代、信息跳跃和概念漂移；
- 在保留作者声音的前提下，把文章重新组织成连续可听的表达。

不适合：

- 根据一个标题重新创作完整节目；
- 给文章增加新的事实、案例或观点；
- 把长文大幅压缩成短视频脚本；
- 生成表演提示、音效脚本或虚构主持互动。

## 什么算合格

一份口播稿至少应该做到：

- 原文事实、观点、关系、判断和作者声音没有被改写成另一套意思；
- 当前句子需要的前提已经出现，不依赖回看文章才能理解；
- 聊天动作来自内容本身，而不是平均撒在全文；
- 句子像现实中会说的话，但没有因为口语化变得松散；
- 同一核心概念保持稳定，不发生无依据的近义词漂移；
- 没有无信息铺垫、重复解释、模型式互动和自动升华；
- 实际朗读自然、连续，可以直接进入目标音频流程。

SmartRewrite 追求的不是“更像口语的文字”，而是让已经成立的内容，在声音里仍然成立。
