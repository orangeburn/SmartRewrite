# SmartRewrite

SmartRewrite 是一个面向内容转写的 AI Skill 项目。

它关注的不是“怎样让模型把文字写得更像口语”，而是一个更基础的问题：同一组内容进入不同媒介以后，信息应该以什么顺序出现。

文章依赖页面。读者可以停顿、回看、跳读标题，也可以通过段落、加粗和列表查询前文。口播依赖时间。听众只能跟随声音向前移动，无法随时返回某个句子，确认“这”“它”指什么，或者等待几分钟以后再补齐当前结论缺少的前提。

因此，口播转写不是简单润色，也不是重新创作。它需要把原文已有的内容，根据听觉场景重新排列。

## 当前能力

仓库目前包含一个 Skill：

### article-to-spoken-script

将中文文章转写成适合播客、音频节目、视频旁白、人工朗读和 TTS 的口播稿。

完整规则见 [`article-to-spoken-script/SKILL.md`](./article-to-spoken-script/SKILL.md)。

## 口播转写是什么

口播转写遵循一个基本原则：

> 最小新增，充分重排。

原文提供全部内容：事实、观点、案例、判断、限制条件和作者声音。Skill 不替作者增加新的事实、例子或结论，但可以重新组织这些内容出现的顺序。

允许的操作包括：

- 将后文已有的必要解释前置。
- 将分散在不同段落中的同一条推理合并。
- 在结论前回填原文已经表达过的前提。
- 将概念定义移动到第一次被需要的位置。
- 拆分过载句子，合并割裂内容。
- 通过核心概念复现连接相邻段落。
- 删除因内容移动而产生的重复。

必须保持不变的是：

- 原文事实与数据
- 核心观点
- 因果关系
- 判断强度
- 不确定性和保留意见
- 作者态度与个人风格
- 整体论证方向

口播稿不需要忠实于原文排版，也不需要机械保留原句、原段落和原有信息顺序。

## 为什么需要重新排列

书面文章允许适当跳跃。

作者可以先给出一个判断，稍后再解释原因；可以用“这”“那”“它”指代前文；也可以让标题承担转折。读者发现理解中断时，可以回看、停顿或继续读到后文，再重新解释前面的句子。

听众没有同样的查询能力。

当一句话需要后文的信息才能成立，听众必须暂时把未解决的问题保存在工作记忆中，同时继续接收新内容。理解缺口越多，认知负担越高。

SmartRewrite 要求转写时持续判断：

> 听众理解当前句子所需的信息，是否已经在听觉时间线上出现。

如果没有，应从原文其他位置提取必要内容，进行局部前置、回填、合并或重排。

## 核心设计原则

### 内容忠实，表达重组

事实、观点、因果和作者声音必须忠实。句子、段落和信息出现顺序可以根据目标媒介调整。

### 局部语义闭环

当前结论所需的前提应当已经出现。口播稿不能要求听众长期等待后文，才能理解几分钟前听到的判断。

这不意味着每个段落都要写成独立小作文，而是不能保留会阻断当前理解的书面跳跃。

### 明确指代

文章里的“这、那、它、这种情况”可能要求听众回忆较远的前文。指代对象过远、存在多个候选对象，或者指向一整段抽象论述时，应重新说出必要的核心概念。

### 真实连接

段落连接优先依靠概念延续、因果延续、对比延续和对象延续，而不是“说到这里”“接下来我们看”等通用过渡套话。

### 拒绝模型腔

Skill 限制以下常见问题：

- 把一句自然完整的话拆成多个无信息增量的短句。
- 自动加入“你可能会问”等虚构互动。
- 每段都提出问题、解释并总结。
- 为了显得完整而补充新例子、新背景或结尾升华。
- 把作者语言改成主持人腔、讲师腔或标准化 AI 文风。

### 拒绝机械保守

只替换代词、拆长句和调整数字，并不足以完成口播转写。

如果原文的信息顺序依赖阅读环境，Skill 必须重新排列原文已有内容，而不是以“忠实”为由保留理解断点。

## 使用方式

在支持 Skill 目录的环境中，可以直接使用 `article-to-spoken-script` 目录。

在只能配置项目指令的环境中，可以复制 [`SKILL.md`](./article-to-spoken-script/SKILL.md) 的内容，并将完整文章作为输入。

推荐指令：

```text
使用 article-to-spoken-script，将下面的文章转写成适合直接朗读的口播稿。
忠实保留原文事实、观点、判断和作者声音，根据听觉理解的依赖关系，重新排列原文已有内容。
不得添加新事实、新案例或新结论。
```

输入最好包含：

- 完整文章正文
- 目标用途，例如播客、视频旁白或 GPT-SoVITS
- 目标时长或字数限制，如有
- 必须保留、调整或删除的内容，如有

默认输出只包含标题和完整口播正文。

## 适用场景

这个 Skill 适合：

- 将公众号文章转换成播客文字稿。
- 将长文章转换成视频旁白。
- 为 GPT-SoVITS 等 TTS 工具准备可直接朗读的文本。
- 保留作者风格，同时修复书面信息顺序在听觉场景中的问题。
- 修正已有口播稿中的悬空判断、模糊指代和段落割裂。

它不适合：

- 根据一个标题重新创作完整节目。
- 为文章增加新的事实、案例或观点。
- 将长文章大幅缩写成短视频脚本。
- 生成主持人互动、表演提示或音效脚本。

这些任务需要独立 Skill，不应混入口播转写流程。

## 判断结果是否合格

一份合格的转写结果应同时满足：

1. 原文事实、观点、判断和作者声音仍然清楚可辨。
2. 信息顺序已经适应只能向前收听的场景。
3. 当前句子所需的前提已经出现。
4. 原文允许的阅读跳跃已经被补齐或重排。
5. 没有加入原文之外的新内容。
6. 段落之间存在真实的语义连接。
7. 核心概念得到必要复现。
8. 模糊指代已经被处理。
9. 没有模型式扩写、自问自答和重复总结。
10. 实际朗读自然、连续，并可直接用于 TTS。

SmartRewrite 的目标不是少改几句话，也不是让模型写得更多，而是让已有内容以更适合目标媒介的顺序出现。
