# SmartRewrite

SmartRewrite 用来把已经写好的中文文章，重建成适合播客、旁白、人工朗读和 TTS 的口播稿。

文章和口播是两种不同的媒介。文章允许读者停下来、回看、跳读标题，也可以依赖段落、加粗和上下文寻找前文。口播只能沿时间向前。听众听到一句话时，如果理解它所需的前提还没出现，或者“这、它、这个问题”需要回头查找，理解就会中断。

SmartRewrite 会重新组织原文已有的信息，再处理聊天结构、口语句法和朗读问题。事实、观点、概念边界、判断强度和作者声音保持不变。

## article-to-spoken-script

`article-to-spoken-script` 是仓库中的文章转口播 Skill。

完整规则见 [`article-to-spoken-script/SKILL.md`](./article-to-spoken-script/SKILL.md)。

一次转写包含四层处理：

1. **Content Fidelity**：保留事实、观点、关系、判断强度、概念边界和作者声音。
2. **Conversational Reconstruction**：恢复一个人面对另一个人解释和思考时的内容推进。
3. **Spoken Syntax Reconstruction**：把书面句法改成日常表达中真正会说出来的中文。
4. **Audio Delivery**：处理指代、句长、数字、英文、标点和 TTS 朗读问题。

核心原则：

> 最小新增，充分重排，概念稳定，信息紧凑。

## 转写重点

同一句话写下来可能很顺，真正说出来却很别扭。一段文章单独看逻辑完整，连续听时却可能缺前提。把一句话拆成四五句，也可能让信息推进变慢。

SmartRewrite 主要处理以下问题。

### 听觉顺序

当前判断需要的前提，应尽量在判断之前出现。

原文可以把定义放在后面、把案例和观点隔开、让标题承担转折。口播需要把这些视觉结构转换成连续可听的信息顺序。必要时可以前置、合并、拆分或移动原文已有内容。

### 内容推进

相邻句子之间要有真实关系，例如继续解释、补条件、举例、修正判断、回到主线或形成结论。

反问、短梗和自我回应只在内容本身存在冲突、态度、修正或转折时出现。一段材料可以连续讲很久，不需要额外制造聊天节点。

### 口语句法

口语化主要处理句法摩擦。

能直接说清的命题保持直接。书面关联句只有在拆开后更容易说、更容易听时才拆。已经明确的主语可以省略，但不能制造新的指代歧义。

信息密度不因口语化而下降。

### 概念稳定

同一个核心概念默认使用稳定的词。

SmartRewrite 会从当前原文中动态识别核心术语、承担论证作用的关键词，以及容易被近义词替换但范围不同的概念。句子可以重写，概念保持原来的范围和含义。

口播里重复一个准确的核心词，通常比换一个看似自然的近义词更安全。

### 作者声音

事实、观点、判断强度、不确定性、讽刺、保留意见和原文结论都需要保留。

Skill 不补行业背景，不新增案例，不制造新金句，也不自动升华结尾。

## 允许的调整

在不改变原文命题的前提下，可以：

- 前置理解当前判断所需的解释和条件；
- 合并分散在不同位置的同一条推理；
- 把案例移动到它支持的观点附近；
- 在第一次需要时解释概念；
- 拆开不适合朗读的书面句法；
- 省略已经明确且不会产生歧义的重复信息；
- 复现必要的核心概念；
- 删除重排以后产生的重复；
- 恢复原文能够支持的观察、反应、限定、修正和回收过程。

这些调整只改变表达和顺序，不增加新的事实、观点、因果、类比或作者经历。

## 边界

以下做法不属于 SmartRewrite 的目标：

- 堆叠“其实、所以、你看、就是说”等口头连接词；
- 虚构听众问题和互动；
- 每隔一段安排反问或梗；
- 把每句话都拆成短句；
- 为了松弛感增加无信息前奏；
- 同一个意思换几种说法重复一遍；
- 为了避免重复随意替换核心概念；
- 把作者语言改成主持人腔、讲师腔或标准 AI 播客文风。

## 使用方式

在支持 Skill 目录的环境中，直接使用 `article-to-spoken-script`。

如果环境只能配置项目指令，可以复制 [`SKILL.md`](./article-to-spoken-script/SKILL.md) 的内容，再提供完整文章。

```text
使用 article-to-spoken-script，将下面的文章转写成可以直接朗读的口播稿。
保留原文事实、观点、概念边界、判断强度和作者声音。
不要增加新事实、新案例或新结论。
```

输入最好包含：

- 完整文章正文；
- 用途，例如播客、视频旁白或 GPT-SoVITS；
- 时长或字数限制，如有；
- 必须保留、删除或调整的内容，如有；
- 节目名称、讲述者名称或固定开场语，如需要。

默认只输出标题和完整口播正文，不输出内部分析、重排方案和检查过程。

## 目录结构

```text
SmartRewrite/
├── README.md
└── article-to-spoken-script/
    ├── SKILL.md
    ├── references/
    │   └── conversational-discourse.md
    └── agents/
        └── openai.yaml
```

`SKILL.md` 定义完整转写协议和验收标准。

`references/conversational-discourse.md` 定义聊天式重建、口语句法、信息密度和概念稳定的细化规则。

`agents/openai.yaml` 提供 Skill 的展示信息和默认调用提示。

## 适用范围

适合：

- 公众号文章转播客文字稿；
- 长文章转视频旁白；
- 为 GPT-SoVITS 等 TTS 准备可直接朗读的文本；
- 修正已有口播稿里的书面句法、模糊指代、信息跳跃和概念漂移；
- 在保留作者声音的前提下，把文章重新组织成连续可听的表达。

超出当前 Skill 范围的任务包括：

- 根据一个标题重新创作完整节目；
- 给文章增加新的事实、案例或观点；
- 把长文大幅压缩成短视频脚本；
- 生成表演提示、音效脚本或虚构主持互动。

## 验收

一份可用的口播稿应满足：

- 原文事实、观点、关系、判断和作者声音保持一致；
- 当前句子需要的前提已经出现；
- 聊天动作来自内容本身，没有平均撒在全文；
- 句子适合现实口头表达，同时保持信息紧凑；
- 同一核心概念保持稳定；
- 没有无信息铺垫、重复解释、虚构互动和自动升华；
- 实际朗读自然、连续，可以直接进入目标音频流程。

SmartRewrite 让已经成立的内容，在声音里继续成立。
